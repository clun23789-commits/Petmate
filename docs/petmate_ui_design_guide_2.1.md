# Petmate UI 设计思路文档｜2.1

> 事实源归属：本文档维护视觉风格、组件语言、页面状态呈现和概念图生成约束。产品业务规则以 `petmate_product_direction_1.2.1.md` 为准，页面路由 / 弹窗 / tabbar 以 `petmate_page_structure_flow_2.3.md` 为准，开发验收清单以 `ui_optimization_checklist.md` 为准。

适用对象：Petmate 微信小程序 UI 概念图生成、页面原型设计、前端开发沟通、后续视觉一致性检查。  
修订目标：在保留 1.0 版产品方向的基础上，修正页面与状态混淆、术语不统一、核心页面状态不足、结果互动页信息过密、权益扣次文案不够准确、image2 生成约束不够硬等问题。

## 0. 修订说明

本版不是重新定义 Petmate 产品，而是在既有方向上进行 UI 文档修订。

本版重点修改如下：

1. 统一 AR 权益对象为“当前宠物作品”或“当前作品 ID”，不再使用“宠物模板”描述真实用户作品的付费权益。
2. 将“支付成功 / 权益到账”从独立页面调整为“支付页内部状态”，避免页面与状态混淆。
3. 补充核心页面的默认态、空态、加载态、失败态、已购态、未购态、权益异常态等状态要求。
4. 重构结果互动页信息层级，避免六维反馈、补色、再次优化、进入 AR、分享等操作全部堆在首屏。
5. 将“提交后使用 1 次优化次数”改为“预占 1 次，优化成功返回可用结果后正式扣减，失败不扣减”。
6. 明确上传页中正脸、侧面、全身照片是推荐素材结构，不应被设计成僵硬的三张强制上传表单。
7. 增加统一组件规范和 image2 生成硬性约束，减少概念图跑偏。
8. 增加 UI 修改优先级，避免平均用力，优先修正核心转化链路页面。

## 1. 产品定位与体验主线

### 1.1 产品定位

Petmate 是一个以微信小程序为载体的 AI 宠物数字形象产品。

它基于用户上传的单只猫或狗照片，生成具有高识别度的宠物数字形象，并提供当前宠物作品的 AR 展示能力。

Petmate 的核心价值不是宠物社区、宠物商城、会员订阅或重度养成，而是帮助用户快速获得一个“第一眼能认出是自己宠物”的数字化展示资产。

### 1.2 核心体验闭环

Petmate 的核心体验闭环为：

```text
看到效果 → 解锁试用 → 上传宠物照片 → 生成 AI 宠物数字形象 → 判断像不像 → 结构化反馈与优化 → 满意后进入 AR 展示 → 为当前宠物作品付费解锁 AR 权益
```

所有页面设计都应服务于这条主线。任何会让产品偏向社区、商城、会员中心、复杂账户系统、任务系统或游戏养成的 UI 元素，都应被删除或替换。

### 1.3 UI 设计需要解决的核心问题

Petmate 的 UI 设计重点不是堆功能，而是解决以下用户问题：

1. 我能否快速看懂这个产品能生成什么效果？
2. 我是否相信上传照片后能生成接近自家宠物的数字形象？
3. 如果生成结果不够像，我是否知道如何反馈、补图和优化？
4. 广告试用、优化次数和 AR 付费权益是否清楚可信？
5. 付费前，我是否明确知道购买的是当前单个宠物作品的 AR 展示权益？
6. 付费后，我是否知道同一宠物作品再次进入 AR 不会重复收费？
7. 出错时，我是否知道权益是否保留、次数是否扣减、下一步该怎么恢复？

### 1.4 UI 设计的核心判断标准

后续判断任意页面是否合格时，优先看五点：

- 是否仍然围绕“生成自己的宠物数字形象”展开？
- 是否清楚表达“广告试用”和“AR 付费”的边界？
- 是否清楚表达“当前宠物作品 AR 权益”而非会员权益？
- 是否让用户知道失败后权益和次数如何处理？
- 是否保持微信小程序的轻量、干净、温和，而不是变成营销页、社区页或后台页？

## 2. 产品边界、术语与硬性禁令

### 2.1 产品边界引用

UI 设计不得扩展产品方向文档之外的新业务能力。完整产品禁令、服务分层、AR 权益、优化次数和上传规则，以 `petmate_product_direction_1.2.1.md` 为准。

本文档只补充 UI 侧表达原则：界面应保持中文为主、宠物友好、温和可信，不做重游戏化、重营销海报、强赛博荧光或后台管理表格式体验。

### 2.2 image2 / 概念图生成统一硬性禁令

后续所有页面概念图生成提示词中，都应加入以下约束摘要；完整禁令词清单不在本文重复维护，以产品方向文档为准：

```text
不得出现会员化、商城化、社区化、游戏化、医疗化、后台管理化或英文主界面表达。
tabbar 只按页面结构文档允许范围出现。
AR 权益必须表述为“当前宠物作品”或“当前作品”的 AR 展示权益，不要写成会员权益、全作品权益或模板通用权益。
失败、权益保留、次数不扣减等信息应使用柔和浅绿色或可信提示卡表达，不要用强警告风格制造焦虑。
```

### 2.3 商业化边界

Petmate 的商业化逻辑应始终保持清楚：

| 层级 | 提供内容 | UI 表达重点 |
|---|---|---|
| 免费层 | 浏览案例、观看 AR 成果预览、体验官方示例模型 | 建立效果预期，不开放真实宠物导入 |
| 广告试用层 | 观看激励广告后获得上传生成权限和有限次数结果优化能力 | 说明广告换取的权益，不混入 AR 付费权益 |
| 付费层 | 为当前宠物作品解锁 AR 展示权益 | 单作品、可反复进入、失败后权益保留 |

设计中应避免让用户误以为：

- AR 是会员权益。
- 一个作品付费后可以覆盖所有宠物作品。
- AR 失败需要重新支付。
- 系统异常会消耗用户优化次数。
- 免费示例模型等同于真实宠物生成结果。
- 细节补色可以修改体型、脸型、耳朵、尾巴等模型结构。

### 2.4 术语统一规则

为了避免用户误解，UI 文案、页面标题、提示卡片和按钮文案应统一使用以下术语。

| 推荐使用 | 避免使用 | 说明 |
|---|---|---|
| 当前宠物作品 | 单个宠物模板 | 真实用户生成结果应称为作品，不称为模板 |
| 当前作品 AR 权益 | 会员 AR 权益 | AR 是单作品权益，不是会员权益 |
| 官方示例模型 | 官方模板宠物 / 模板权益 | 示例仅用于免费体验，不等于真实宠物结果 |
| 结果优化次数 | 修改次数 / 编辑次数 | 强调是重新生成类优化次数 |
| 预占 1 次优化次数 | 提交后扣 1 次 | 成功返回可用结果后才正式扣减 |
| 细节补色 | 自由编辑 / 模型编辑 | 只处理贴图层局部颜色和小瑕疵 |
| AR 展示 | AR 特权 / AR 会员 | 避免会员感或游戏特权感 |

## 3. 统一视觉风格

### 3.1 整体气质

Petmate 的界面气质应保持：

- 温和
- 干净
- 治愈
- 宠物友好
- 可信
- 轻科技感
- 微信小程序轻量化风格

整体观感应像一个可以真实落地的小程序，而不是纯插画海报、营销长图、游戏活动页或后台管理系统。

### 3.2 色彩方向

推荐色彩方向：

| 用途 | 推荐方向 | 注意事项 |
|---|---|---|
| 页面背景 | 奶油白 / 浅米色 | 不使用大面积纯黑、深蓝、强紫 |
| 卡片背景 | 浅米色 / 暖白色 | 圆角、轻阴影、柔和分区 |
| 主按钮 | 暖橙色 | 用于核心行动，不要滥用 |
| 成功状态 | 柔和浅绿色 | 用于权益保留、已到账、可恢复 |
| 标题与标签 | 柔和棕色 / 深灰棕 | 避免纯黑压迫感 |
| 风险提示 | 柔和红棕色 | 删除、失败等场景使用，不要强刺激 |
| 次要按钮 | 浅色描边 / 米色按钮 | 与主按钮形成层级差异 |

### 3.3 布局语言

界面应遵循微信小程序的轻量化布局习惯：

- 手机竖屏界面。
- 顶部保留微信小程序胶囊按钮区域。
- 只有作品页、案例页、我的页这三个一级页面可使用底部 tabbar。
- 除上述三个一级页面外，所有页面、页面状态和弹窗均不得出现底部 tabbar。
- 以圆角卡片作为主要信息容器。
- 使用柔和阴影和清晰留白。
- 主按钮明显，次按钮弱化但可识别。
- 页面信息不宜过密，避免变成后台面板或复杂表单。
- 高风险说明、权益说明和扣次说明必须提前、清楚、可信。

### 3.4 统一组件规范

后续 33 张页面 / 状态 / 弹窗 UI 概念图包含页面状态和弹窗，不等于 `app.json` 中的独立页面路由数量；其中实际小程序路由约 29 个，其余为页面状态或弹窗组件，不一定对应独立页面目录，应尽量复用以下组件语言。

#### 3.4.1 顶部区域

- 保留微信小程序顶部胶囊按钮区域。
- 页面标题左对齐或居中均可，但同一批页面应统一。
- 二级页面左上角应有返回能力。
- 顶部不放过多运营信息，不做广告横幅。

#### 3.4.2 卡片

- 使用大圆角浅色卡片承载主要信息。
- 卡片内信息分组清晰，避免超过 3 个主要信息块。
- 权益、状态、失败恢复等高敏感信息使用独立提示卡，不混在普通说明文字里。

#### 3.4.3 按钮

- 主按钮使用暖橙色，胶囊形或大圆角矩形。
- 次按钮使用浅米色、描边或文字按钮。
- 删除、退出等风险操作不使用大面积强红，采用柔和红棕色或二次确认弹窗。
- 同一页面最多突出一个主按钮。

#### 3.4.4 状态标签

- 使用小圆角胶囊标签。
- 常见标签：已生成、生成中、生成失败、可继续优化、已解锁 AR、权益已保留、优化次数未扣减。
- 标签文字应短，避免长句堆叠。

#### 3.4.5 弹窗

- 弹窗不是独立页面。
- 背景使用当前页面半透明遮罩。
- 弹窗居中，圆角卡片，信息简短。
- 弹窗只承载单一确认任务，例如删除作品、修改昵称、退出登录。

#### 3.4.6 状态提示

- 成功、权益到账、权益保留、次数未扣减：使用柔和浅绿色。
- 加载、等待、生成中：使用轻科技感进度或阶段提示。
- 失败、异常、不可用：先解释原因，再说明权益与次数，再给恢复动作。

### 3.5 字体与信息层级

界面文案应满足：

- 中文为主。
- 标题清楚，层级分明。
- 说明文案短而明确。
- 按钮文案直接表达动作。
- 状态标签简洁可读。
- 避免长段密集说明。
- 权益、扣次、失败补偿等高敏感信息必须提前展示。
- 所有付费相关文案必须写清“当前宠物作品”。

### 3.6 宠物数字形象视觉定义

Petmate 的宠物数字形象应采用：

- 轻低多边形风格。
- 插画化 3D 表达。
- 可爱但不过度卡通。
- 适合微信小程序展示和 AR 场景运行的轻量模型视觉。

模型视觉应重点保留真实宠物的高识别特征：

- 毛色
- 花纹
- 耳型
- 尾巴
- 脸部轮廓
- 体型特征

不应追求：

- 写实毛发。
- 影视级真实皮毛。
- 复杂表情系统。
- 强游戏角色风。
- 高自由度模型结构编辑。
- 过度夸张的卡通拟人化。

设计目标不是极致写实，而是让用户第一眼能认出“这是我的宠物”。

## 4. 页面体系与页面状态划分

### 4.1 页面组总览

Petmate 的页面按用户任务分为七组。

| 页面组 | 主要任务 | 包含页面 / 状态 |
|---|---|---|
| 创作入口与生成链路 | 从理解产品到完成首次生成 | 作品页、开始创作页、广告解锁说明页、上传与质检页、生成等待页 |
| 结果判断与优化链路 | 判断像不像，并通过反馈继续优化 | 结果互动页、定向补图页、细节补色页、异常恢复页 |
| AR 付费与展示链路 | 说明 AR 权益，完成单作品付费并进入展示 | AR 使用说明页、支付页、AR 展示页、AR 失败说明页；支付成功 / 权益到账属于支付页状态 |
| 作品管理链路 | 回看、管理和再次进入作品 | 已生成的宠物页、作品详情页、删除作品确认弹窗 |
| 案例与示例体验链路 | 通过案例、视频和官方示例建立效果预期 | 案例页、搜索页、视频详情页、案例详情页、官方示例模型体验页 |
| 分享传播与新用户转化链路 | 承接分享访问并引导新用户 | 分享落地页、分享转化页 |
| 我的与辅助链路 | 帮助、权益说明、反馈和账户轻管理 | 我的页、权益说明页、帮助页、帮助详情页、投诉与反馈页、联系我们页、个人信息页、修改昵称弹窗、退出登录确认弹窗 |

后续概念图数量可按页面、状态、弹窗分别管理，但实际开发拆分以 `petmate_page_structure_flow_2.3.md` 为准。

### 4.2 页面、状态、弹窗呈现规则

本文档只规定 UI 呈现方式：

- 页面：按完整竖屏小程序界面设计，承载清晰主任务。
- 状态：在原页面结构内变化，避免画成另一个互不相干的页面。
- 弹窗：表现为依附当前页面的轻量确认或输入层，不画成完整页面。

### 4.3 底部 tabbar 呈现规则

tabbar 允许范围以页面结构文档为准。UI 概念图只需确保：允许出现 tabbar 的一级页面使用统一底部导航样式；其他页面、状态和弹窗不额外绘制底部 tabbar。

### 4.4 核心页面状态矩阵

| 页面 | 必须考虑的状态 |
|---|---|
| 作品页 | 无作品、有作品、生成中、生成失败、已购 AR、未登录 / 游客 |
| 广告解锁说明页 | 首次创作来源、补充优化次数来源、权益恢复来源、广告加载失败、广告成功但权益未到账 |
| 上传与质检页 | 未上传、部分上传、素材足够、素材偏少但可继续、素材不可用、上传失败、权限异常 |
| 生成等待页 | 排队中、识别中、生成中、优化中、生成成功、生成失败、用户离开后任务继续 |
| 结果互动页 | 首次结果、剩余次数充足、剩余次数为 0、待提交反馈、优化中、已购 AR、未购 AR、结果不可用 |
| 定向补图页 | 补图建议态、已上传补图、补图不合格、预占次数说明、上传失败 |
| 细节补色页 | 可编辑、修改中、保存成功、保存失败、当前模型不可编辑 |
| AR 使用说明页 | 未购、已购、设备可能不支持、从结果页进入、从作品详情页进入 |
| 支付页 | 待支付、支付中、支付成功且权益到账、支付成功但权益确认中、支付失败、支付取消、当前作品已拥有权益 |
| AR 展示页 | 初始化中、寻找平面、放置成功、权限异常、环境不满足、设备性能不足、分享中 |
| AR 失败说明页 | 权限未开启、光线不足、未识别平面、设备性能不足、权益已保留、重试成功 |
| 异常恢复页 | 广告异常、上传异常、生成异常、权益已保留、次数未扣减、可重新尝试、需反馈 |

#### 状态验收方式

状态验收分为三类，避免无限制补图，也避免关键状态漏设计。

| 类型 | 验收方式 | 示例 |
|---|---|---|
| A 类：必须单独出概念图 | 作为独立概念图或明确的状态图验收 | 支付成功 / 权益到账状态、AR 失败说明页、异常恢复页、删除作品确认弹窗 |
| B 类：可在页面主图中以状态卡表达 | 不强制单独出图，但必须在对应页面设计中有清晰状态表达 | 已购 / 未购 AR、生成中、素材偏少但可继续、优化次数为 0、权益已保留 |
| C 类：进入开发验收清单 | 不强制单独出图，开发实现与测试时必须覆盖 | 用户离开后任务继续、列表加载失败、分享加载异常、重新查询权益、提交反馈失败 |

概念图验收时，A 类状态必须能被直接看到；B 类状态可以通过标签、提示卡、按钮变化或页面副状态表达；C 类状态不要求逐一画成单独概念图，但必须进入前端状态覆盖与测试清单。

## 5. UI 修改与生成优先级

## 6. 创作入口与生成链路设计

### 6.1 作品页 / 首页

#### 设计目标

作为默认首页，展示用户当前宠物作品。无作品时引导开始创作，同时保留进入“已生成的宠物页”的固定入口；有作品时提供回看、继续进入作品详情和查看全部已生成作品的入口。

#### 核心内容

- 顶部标题：“作品”。
- 副标题：“记录你的宠物数字形象”。
- 当前作品卡片：宠物数字形象预览、昵称、宠物类型、生成状态。
- 状态标签：已生成、可继续优化、已解锁 AR、生成中、生成失败。
- 主按钮：无作品时为“开始创作”，有作品时可为“查看作品”或“继续优化”。
- 快捷入口区：固定包含“已生成作品”入口，用于进入“已生成的宠物页”；也可包含“案例页”“帮助与权益”等辅助入口。
- 空状态：温和宠物插画和创作引导。
- 底部 tabbar：作品、案例、我的。

#### 必须覆盖的状态

- 无作品空状态。
- 有当前作品状态。
- 当前作品生成中状态。
- 当前作品生成失败状态。
- 当前作品已解锁 AR 状态。
- 游客或未登录状态。
- 无作品状态下仍显示“已生成作品”入口，点击后进入已生成作品页的空状态。
- 有作品状态下显示“已生成作品”入口，点击后进入作品列表。

#### 设计重点

首页要让用户一眼理解这是“宠物数字形象作品页”，不是社区首页、相册首页或商城首页。

首页不应急着让用户付费，也不应堆满案例内容。它的任务是承接当前作品和创作入口。

作品页不是只负责展示当前作品，还必须提供进入完整作品管理列表的入口。该入口应清晰、稳定、可被用户发现，不应隐藏在作品卡片内部。

#### 边界

不在首页直接做照片上传、结构化反馈、细节补色、支付或 AR 展示。
“已生成作品”入口不属于底部 tabbar，不应把“已生成的宠物页”提升为一级页面。

---

### 6.2 开始创作页

#### 设计目标

向用户说明创作流程、支持范围和上传前准备要求，并引导进入广告试用。

#### 核心内容

- 顶部标题：“开始创作”。
- 主视觉：宠物照片逐步变成轻低多边形 3D 数字形象。
- 流程说明：上传猫狗照片、生成 AI 宠物数字形象、判断像不像并优化、满意后进入 AR 展示。
- 支持范围提示：“目前支持单只猫 / 狗”。
- 上传前准备提示：“建议准备正脸照、侧面照、全身照”。
- 广告试用权益卡：观看激励广告后，可获得上传生成权限和 3 次结果优化次数。
- 主按钮：“解锁试用”。
- 次入口：“先看官方示例模型”。

#### 设计重点

降低用户理解成本，让用户知道“接下来要做什么、会获得什么、还不能获得什么”。

页面应清楚说明真实宠物上传需要先进入广告试用，但不能让广告看起来像强制付费墙。

#### 边界

不直接上传照片，不直接播放广告，不做结果优化和 AR 付费。

---

### 6.3 广告解锁说明页

#### 设计目标

在用户观看激励广告前，清楚说明本次广告试用获得的权益、边界和失败恢复规则。

#### 核心内容

- 顶部标题：“解锁试用”。
- 当前来源说明：首次创作、补充优化次数、权益恢复。
- 权益卡片：上传宠物照片、生成基础 AI 数字形象、获得 3 次结果优化次数。
- 规则说明：系统异常或生成失败不扣次数；广告试用不包含 AR 付费权益；照片仅用于本次生成与优化。
- 小型流程：看广告 → 上传照片 → 生成模型 → 结果优化。
- 主按钮：“观看广告并解锁”。
- 次按钮：“暂不解锁”。

#### 必须覆盖的状态

- 首次创作来源。
- 从结果互动页进入，原因是优化次数不足。
- 用户已获得广告权益但流程中断，进入权益恢复状态。
- 广告加载失败。
- 广告观看成功但权益未到账。
- 用户取消广告。

#### 设计重点

可信、清楚、不过度商业化。重点不是刺激点击，而是建立试用信任。

如果是“补充优化次数”来源，页面应明确告诉用户：观看广告后将补充新的结果优化次数，并返回当前作品的结果互动页。

#### 边界

不承载照片上传、模型生成、结果反馈、AR 购买和作品管理。

---

### 6.4 上传与质检页

#### 设计目标

引导用户上传清晰、有效的宠物照片，并通过质检提示提高生成质量。

#### 核心内容

- 顶部标题：“上传照片”。
- 主上传区：优先上传一张清晰正脸照，作为首次生成的主输入素材。
- 建议补充素材区：侧面照、全身照以建议卡片形式展示，不与主图并列为强制三项表单。
- 上传按钮与缩略图占位：主图上传区更突出，补充素材区更轻量。
- 照片要求提示：单只猫狗、光线清晰、不遮挡脸部和身体、尽量包含完整花纹。
- 质检反馈区域：主图是否清晰、是否识别为单只猫狗、是否建议补充侧面花纹或全身轮廓。
- 主按钮根据状态变化：开始生成、继续生成，可稍后补图、请补充照片、请更换照片。

#### 必须覆盖的状态

- 未上传照片。
- 只上传了主图。
- 素材足够，可以开始生成。
- 素材偏少但仍可继续生成。
- 素材质量过低，不能生成。
- 上传失败。
- 相册或相机权限异常。

#### 设计重点

页面应像温和、专业的上传指导，而不是普通相册选择页。重点是让用户明白“为什么建议这些照片”。

不应让用户感觉必须一次性上传三张照片才能继续，否则会提高首次试用门槛。设计上应明确区分“最低可生成标准”和“建议补充素材”：达到最低标准即可继续生成，补充更多照片只是提高相似度的建议。

#### 推荐文案

- “建议先上传一张清晰正脸照。”
- “侧面照有助于识别花纹和体型。”
- “全身照有助于识别尾巴和整体轮廓。”
- “当前素材可以生成，补充更多照片可能让结果更像。”

#### 边界

不承载广告观看、结果反馈、优化次数扣减、细节补色、AR 支付或 AR 展示。

---

### 6.5 生成等待页

#### 设计目标

在 AI 生成过程中给用户明确等待反馈，避免用户误以为页面卡住、任务丢失或重复提交。

#### 核心内容

- 顶部标题：“正在生成”。
- 主视觉：宠物照片逐渐变成立体低多边形 3D 宠物数字形象。
- 进度阶段：正在识别宠物特征、正在生成数字形象、正在优化毛色与花纹。
- 当前阶段高亮。
- 温和提示：“生成过程中请勿重复提交，离开页面后任务仍会继续”。
- 小卡片说明：“系统异常不会扣减优化次数”。
- 次按钮：“返回作品页查看状态”。

#### 必须覆盖的状态

- 排队中。
- 正在识别。
- 正在生成。
- 正在优化。
- 生成成功，自动进入结果互动页。
- 生成失败，进入异常恢复页。
- 用户离开页面但任务继续。

#### 设计重点

等待页不是普通 loading 页，而是承担“安定感”和“任务确定性”的页面。

如果本次是重新优化，应提示“本次优化已预占 1 次优化次数，若失败不会扣减”。

#### 边界

不承载照片重新上传、结构化反馈、细节补色、主动扣次和 AR 付费。

---

## 7. 结果判断与优化链路设计

### 7.1 结果互动页

#### 设计目标

让用户查看 AI 生成的宠物数字形象，判断像不像自己的宠物，并通过结构化反馈、定向补图或细节补色继续优化。

#### 首屏信息层级

结果互动页是核心页面，但首屏不应堆满所有功能。建议首屏结构如下：

1. 顶部标题：“生成结果”。
2. 宠物数字形象主预览区域，视觉占比最大。
3. 宠物昵称与状态，例如“糖糖 · 已生成”。
4. 剩余优化次数，例如“剩余 3 次优化”。
5. 三个主要操作：判断哪里不像、细节补色、进入 AR。
6. 分享入口可以弱化放在右上角或次级区域。

六维反馈区不建议完整挤在首屏，可放在模型下方的反馈卡片区，或设计为“判断哪里不像”后的展开面板。

“继续优化”不应在用户尚未选择反馈维度前作为唯一主按钮。首屏应先引导用户判断哪里不像；用户完成反馈选择并确认定向建议后，再出现“提交并优化”。

#### 核心内容

- 宠物数字形象主预览区域。
- 旋转、缩放等基础互动提示。
- 宠物昵称与状态。
- 剩余优化次数。
- 六维结构化反馈：毛色、花纹、体型、脸部轮廓、耳朵、尾巴。
- 每个维度可表达“像 / 不像”。
- 定向优化建议卡片。
- 操作按钮：判断哪里不像、细节补色、进入 AR；完成反馈后显示“提交并优化”。
- 分享入口。

#### 六维反馈呈现方式

推荐采用轻量反馈卡，而不是复杂表单。

示例结构：

```text
帮我们判断哪里还不太像
[毛色] 像 / 不像
[花纹] 像 / 不像
[体型] 像 / 不像
[脸部轮廓] 像 / 不像
[耳朵] 像 / 不像
[尾巴] 像 / 不像
```

当用户选择“不像”后，再出现对应定向建议。

#### 定向建议示例

- 毛色不像：建议补充自然光下的正脸或身体照片。
- 花纹不像：建议补充身体侧面或背部花纹照片。
- 体型不像：建议补充全身站立图。
- 脸部轮廓不像：建议补充正脸近景图。
- 耳朵不像：建议补充耳部无遮挡图。
- 尾巴不像：建议补充尾巴完整可见图。

#### 必须覆盖的状态

- 首次生成结果成功。
- 剩余优化次数充足。
- 剩余优化次数为 0。
- 用户已选择部分“不像”反馈。
- 系统建议补图。
- 系统建议细节补色。
- 当前作品已购买 AR 权益。
- 当前作品未购买 AR 权益。
- 优化请求已提交，等待生成。
- 结果不可用或生成异常。

#### 扣次文案规则

结果互动页、定向补图页和生成等待页中涉及优化次数时，统一使用：

> 提交有效优化后将预占 1 次优化次数；优化成功返回可用结果后才正式扣减。若系统异常、生成失败或结果未成功返回，不扣减次数。

用户仅选择“像 / 不像”、查看定向建议、进入反馈面板或取消反馈时，不预占也不扣减优化次数。只有用户明确点击“提交并优化”并进入重新生成流程时，才预占 1 次优化次数。

不要写成：

> 提交后将使用 1 次优化次数。

#### 设计重点

这是核心页面。模型预览必须最突出，反馈区域要清楚但不压迫。“进入 AR”可以明显，但不能让页面变成强付费页。

#### 边界

不承载首次照片上传、广告观看、自由结构编辑、支付动作或 AR 展示本身。

---

### 7.2 定向补图页

#### 设计目标

当用户在结果互动页中对某个维度反馈“不像”时，引导用户补充指定角度或部位照片，以便重新优化。

#### 核心内容

- 顶部标题：“补充照片”。
- 问题原因卡片，例如“你反馈了：花纹不太像”。
- 对应维度标签：毛色、花纹、体型、脸部轮廓、耳朵、尾巴。
- 补图建议。
- 正确示例图与错误示例图。
- 上传补充图片区域和已上传图片缩略图。
- 规则提示：“提交后将预占 1 次优化次数；优化成功后才正式扣减，失败不扣减”。
- 主按钮：“提交并优化”。
- 次按钮：“返回结果页”。

#### 必须覆盖的状态

- 待补图状态。
- 已上传补图状态。
- 补图不符合要求。
- 上传失败。
- 权限异常。
- 优化次数不足，需要回到广告解锁说明页。

#### 设计重点

页面应像温和的拍摄指导，不是普通上传页。重点是告诉用户“该补什么图”。

#### 边界

不承载首次上传完整流程、细节补色、AR 说明或作品管理。

---

### 7.3 细节补色页

#### 设计目标

让用户对已生成模型表面的局部颜色、小面积瑕疵和细小花纹进行轻量修补，不涉及模型结构修改。

#### 核心内容

- 顶部标题：“细节补色”。
- 主区域：宠物模型或局部贴图预览。
- 局部放大区域：尾尖、耳缘、胸口毛色、局部花纹等。
- 工具栏：颜色选择、画笔大小、局部修补、撤销、重做。
- 修改前后对比小卡片。
- 边界说明：“仅支持局部颜色与小面积瑕疵修补，不修改体型、脸型、耳朵或尾巴结构”。
- 主按钮：“保存修改”。
- 次按钮：“放弃返回”。

#### 必须覆盖的状态

- 可编辑状态。
- 修改中状态。
- 保存成功状态。
- 保存失败状态。
- 当前模型不可编辑状态。

#### 设计重点

保持轻量，不要做成专业绘图软件。强调这是局部修补，不是模型结构编辑。

细节补色不应扣减重新生成类结果优化次数。

#### 边界

不承载体型、脸型、耳朵、尾巴等结构级编辑，不承载重新生成流程和 AR 支付。

---

### 7.4 异常恢复页

#### 设计目标

承接广告解锁失败、上传失败、生成失败等试用链路异常，告知用户权益是否保留、次数是否扣减以及下一步如何恢复。

#### 核心内容

- 顶部标题：“遇到一点问题”。
- 温和插画：宠物数字形象坐在小工具箱旁边。
- 异常类型卡片：广告权益未到账、上传失败、生成失败、网络异常。
- 当前权益状态：上传权限已保留、优化次数未扣减、可重新尝试。
- 恢复建议：重新检查任务、返回上传页补充照片、返回生成等待页、联系反馈。
- 主按钮：“重新尝试”。
- 次按钮：“返回开始创作”。
- 辅助入口：“提交问题反馈”。

#### 必须覆盖的状态

- 广告异常。
- 上传异常。
- 生成异常。
- 权益已保留。
- 优化次数未扣减。
- 可恢复。
- 需提交反馈。

#### 设计重点

重点不是报错，而是恢复信任。要清楚展示“没有白白消耗广告权益或优化次数”。

#### 边界

不处理 AR 展示失败，不处理支付失败，不承载作品长期管理。

---

## 8. AR 付费与展示链路设计

### 8.1 AR 使用说明页

#### 设计目标

在用户进入 AR 或支付前，清楚说明 AR 能力、设备条件、权益范围和失败后权益保留规则。

#### 核心内容

- 顶部标题：“AR 展示”。
- 主视觉：手机摄像头画面中，宠物数字形象被放置在真实客厅地面上。
- AR 能力说明：现实空间摆放、缩放、旋转、动作展示、截图或录屏分享。
- 权益说明卡片：本次购买对应当前宠物作品；购买后可无限次进入 AR 展示；同一宠物作品不重复收费；后续优化后仍继承权益；AR 失败后权益仍保留。
- 设备条件提示：需要相机权限和较好的光线环境。
- 主按钮：未购状态显示“购买当前作品 AR 权益”，已购状态显示“进入 AR”。
- 次按钮：“返回结果页”。

#### 必须覆盖的状态

- 当前宠物作品未购买 AR 权益。
- 当前宠物作品已购买 AR 权益。
- 设备可能不满足 AR 条件。
- 从结果互动页进入。
- 从作品详情页进入。

#### 设计重点

可信、清楚，不要出现会员订阅感。

AR 使用说明页不能让用户误以为购买的是全账号权益、全部宠物权益或会员权益。

#### 推荐文案

- “本次购买仅对应当前宠物作品。”
- “购买后，该作品可无限次进入 AR 展示。”
- “后续继续优化该作品，AR 权益仍会保留。”
- “如果 AR 暂时无法使用，权益仍会保留，可稍后重试。”

#### 边界

不承载支付动作本身，不承载 AR 展示本身，不承载结果优化和照片上传。

---

### 8.2 支付页

#### 设计目标

完成当前宠物作品 AR 权益购买，并清楚说明购买对象和权益范围。

#### 核心内容

- 顶部标题：“确认支付”。
- 当前购买作品卡片：宠物昵称、模型缩略图、作品简要信息。
- 权益内容：购买当前宠物作品的 AR 展示权益；可无限次进入；后续优化后仍继承权益；AR 展示失败不丢失权益。
- 价格区域。
- 主按钮：“确认支付”。
- 次按钮：“返回 AR 说明”。
- 底部提示：“不同宠物作品之间 AR 权益不互通”。

#### 支付页状态

支付成功 / 权益到账不再作为独立页面，而是支付页内部状态。

支付页应覆盖以下状态：

1. 待支付状态。
2. 支付中状态。
3. 支付成功且权益到账状态。
4. 支付成功但权益确认中状态。
5. 支付失败状态。
6. 支付取消状态。
7. 当前作品已拥有 AR 权益状态。

#### 支付成功且权益到账状态

核心内容：

- 成功状态：“解锁成功”。
- 成功图标或宠物数字形象庆祝小插画。
- 当前宠物作品卡片：宠物昵称、模型缩略图、AR 权益状态“已解锁”。
- 权益说明：当前宠物作品可无限次进入 AR 展示；后续优化后仍继承权益；AR 失败后权益仍保留。
- 主按钮：“进入 AR 展示”。
- 次按钮：“返回作品详情”。

#### 支付成功但权益确认中状态

核心内容：

- 状态标题：“正在确认权益”。
- 提示：“支付已完成，正在确认当前作品的 AR 权益”。
- 操作：“重新查询”“联系客服”“返回 AR 说明”。
- 禁止出现“再次支付”或“重新购买”按钮。

#### 设计重点

清楚、可信，不做会员页，不做促销风格。

支付页不应出现“VIP”“会员价”“限时会员”“月卡”“年卡”等表达。

#### 边界

不承载 AR 展示体验、结果优化、广告权益发放、照片上传和细节补色。

---

### 8.3 AR 展示页

#### 设计目标

展示用户已购宠物数字形象在现实空间中的 AR 呈现效果。

#### 核心内容

- 手机竖屏摄像头界面。
- 真实室内环境，例如客厅地面或书桌旁。
- 轻低多边形 3D 宠物数字形象被放置在现实空间中。
- 底部操作栏：缩放、旋转、动作、截图、分享。
- 顶部提示：“移动手机，寻找平面”。
- 放置成功后提示：“已放置，可拖动调整位置”。
- 右上角退出按钮。

#### 必须覆盖的状态

- AR 初始化中。
- 正在寻找平面。
- 放置成功。
- 权限异常。
- 环境光线不足。
- 设备性能不足。
- 分享中。

#### 设计重点

让用户感到“这就是值得付费的展示效果”。

AR 展示页应偏沉浸，但仍需保持微信小程序界面可信、轻量、可退出。

#### 边界

不承载 AR 权益购买、结果反馈、细节补色、照片上传和广告解锁。

### 8.4 AR 失败说明页

#### 设计目标

当用户已付费但 AR 展示失败时，清楚说明原因，并强调当前宠物作品的 AR 权益仍然保留。

- 温和插画：宠物数字形象坐在手机旁边。

- 按钮：重新检测、查看权限设置、返回结果页。
- 不出现重新支付按钮。

#### 必须覆盖的状态

- 相机权限未开启。
- 当前光线不足。
- 未识别到平面。
- 设备性能不足。
- 用户修复后重新检测。
- 权益已保留。

#### 设计重点

安抚、可信、清楚。失败不应被设计成二次付费入口。

#### 边界

不承载重新支付、广告解锁、结果优化、模型生成和细节补色。

## 9. 作品管理链路设计

#### 设计重点

这是高风险确认弹窗，要清楚但不要吓人。需强调权益影响。

不承载作品详情展示、结果互动、AR 展示、权益转移、支付退款和账号注销。

这是权益说明，不是会员中心。不能出现会员、VIP、订阅、月卡、年卡。

不直接承接广告观看、支付、照片上传、结果优化和 AR 展示。

### 12.3 帮助页

#### 设计目标

汇总产品使用帮助与问题处理入口，帮助用户理解上传、生成、优化、AR 和权益规则。

#### 核心内容

- 顶部标题：“帮助中心”。
- 常见问题分类卡片：上传与生成、优化次数、AR 使用、支付与权益、失败与恢复。
- 热门问题列表：为什么建议多张照片、生成失败会扣次数吗、AR 失败后权益还在吗、同一宠物需要重复付费吗。
- 联系我们入口。
- 投诉与反馈入口。
- 返回我的页入口。

#### 设计重点

清楚、轻量、可信，不做复杂客服系统。

#### 边界

不承载即时客服聊天、作品修改、广告权益发放、支付和 AR 展示。

---

### 12.4 帮助详情页

#### 设计目标

展示具体帮助内容与操作说明，为用户解决单个问题提供清晰步骤。

#### 核心内容

- 顶部标题：“帮助详情”。
- 帮助标题，例如“生成失败会扣次数吗？”。
- 具体说明内容，分段展示。
- 操作步骤卡：查看当前任务状态、检查是否有可恢复权益、返回上传页或生成等待页重试。
- 相关问题推荐：上传照片有什么要求、AR 失败后怎么办、如何继续优化。
- 仍需帮助入口：“提交反馈”。
- 返回帮助页按钮。

#### 设计重点

内容清楚，避免长篇密集文字。更像小程序帮助文档，而不是客服聊天。

#### 边界

不承载实际业务操作、作品生成、支付、AR 环境检测和账户修改。

### 12.5 投诉与反馈页

#### 设计目标

承接用户投诉、意见反馈与问题上报，收集广告、上传、生成、支付、AR 或体验相关问题。

#### 核心内容

- 顶部标题：“投诉与反馈”。
- 反馈类型选择：上传问题、生成问题、优化次数、支付权益、AR 展示、其他建议。
- 问题描述输入框。
- 图片或截图上传入口。
- 联系方式填写项。
- 提交按钮。
- 提交成功状态：“已收到你的反馈”“我们会尽快查看”。
- 提交失败状态与重试按钮。

#### 设计重点

让用户感觉问题能被记录，但不要承诺即时解决。

#### 边界

不承诺即时解决，不承载支付退款、广告权益自动恢复、作品生成或 AR 展示。

### 12.6 联系我们页

#### 设计目标

提供官方联系渠道，承接用户咨询需求。

#### 核心内容

- 顶部标题：“联系我们”。
- 温和插画：宠物数字形象拿着小信封。
- 官方联系渠道卡：邮箱、微信客服、公众号占位信息，服务时间说明。
- 复制联系方式按钮。
- 联系说明：使用问题、合作咨询、反馈建议。
- 返回帮助页按钮。
- 复制成功提示样式。

#### 设计重点

页面要轻量，不承载投诉表单，不承载即时聊天。

#### 边界

不承载问题表单提交、投诉处理进度查询、作品生成或优化、支付处理和 AR 故障检测。

### 12.7 个人信息页

#### 设计目标

展示并管理用户昵称、头像、登录状态等基础个人信息，保持账户管理能力轻量化。

#### 核心内容

- 顶部标题：“个人信息”。
- 用户头像。
- 用户昵称。
- 登录状态：已登录 / 游客状态。
- 信息卡片：昵称、头像、登录状态。
- 操作入口：修改昵称、退出登录。
- 温和提示：“账户信息仅用于小程序内作品与权益展示”。
- 返回我的页入口。

#### 设计重点

不要做成复杂账户中心，不要加入会员等级、积分、勋章。

#### 边界

不承载作品管理、权益购买、广告解锁、结果优化和帮助详情展示。

### 12.8 修改昵称弹窗

#### 设计目标

在个人信息页内完成轻量昵称修改，不跳转到新页面。

#### 核心内容

- 背景为个人信息页半透明遮罩。
- 居中圆角弹窗。
- 标题：“修改昵称”。
- 当前昵称显示。
- 新昵称输入框。
- 昵称规则提示：“建议 2-12 个字”。
- 按钮：取消、保存。
- 错误状态提示：“昵称不能为空”或“昵称过长”。
- 保存成功后轻提示：“已保存”。

#### 设计重点

这是弹窗，不是独立页面。风格要轻、柔和、简单。

#### 边界

不承载头像修改、登录状态切换、作品相关操作、权益说明和帮助反馈。

---

### 12.9 退出登录确认弹窗

#### 设计目标

确认用户是否退出当前登录状态，防止误触。

#### 核心内容

- 背景为个人信息页半透明遮罩。
- 居中圆角弹窗。
- 温和提示图标或小宠物插画。
- 标题：“确认退出登录？”。
- 说明：“退出后，当前设备将切换为未登录状态。已绑定账号的作品和权益会保留在账号中。”
- 按钮：取消、确认退出。
- 退出失败状态提示：“退出失败，请稍后再试”。

#### 设计重点

不要做成账号注销。只是退出登录确认。

#### 边界

不承载账号注销、作品删除、权益转移、支付处理和帮助反馈。

## 15. 后续使用方式

后续如果继续生成 UI 概念图，不应再把多批提示词反复粘贴成一份长稿，而应按以下方式使用本文档：

1. 先引用本文档中的统一视觉风格、产品边界、术语规则和 image2 通用底座。
2. 再选择对应页面条目，提取该页面的设计目标、核心内容、必须覆盖状态和设计重点。
3. 生成或设计完成后，用 `docs/ui_optimization_checklist.md` 核对是否偏离产品方向，并按第 4.4 节的状态验收方式判断是否需要单独出状态图。
4. 若新增页面，应先判断它是页面、状态还是弹窗，再补充到对应页面组中，避免无序扩张。
5. 若生成结果中出现会员、商城、社区、点赞、关注、排行榜、任务系统等元素，应直接判定为方向错误并重新生成。

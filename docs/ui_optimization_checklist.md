# Petmate UI 优化验收清单

## 1. 使用说明

本清单用于 Petmate 后续每一批 UI 优化的统一验收。每次修改前先确认本批涉及的页面、组件和样式范围；修改后按本清单逐项核对，并将结果写入 `docs/ui_optimization_progress.md`。

本清单遵守以下项目依据：

- `AGENTS.md`
- `docs/CURRENT_STATUS.md`
- `docs/petmate_product_direction_1.2.1.md`
- `docs/petmate_ui_design_guide_2.1.md`
- `docs/petmate_page_structure_flow_2.3.md`
- `docs/smoke_test_checklist.md`

后续 UI 优化应只围绕微信小程序前端体验、视觉一致性、核心链路信任感和信息层级进行；不得在 UI 优化中改变产品边界、权益规则、广告规则、支付规则、AR 规则或页面路由边界。

## 2. 全局产品边界检查

- [ ] 未出现 VIP、会员、月卡、年卡、订阅等会员化表达。
- [ ] 未出现积分商城、购物车、宠物商城等商城化表达。
- [ ] 未出现社区评论、点赞排行、关注、粉丝、聊天广场、排行榜等社区化表达。
- [ ] 未出现抽卡、任务系统、复杂养成等游戏化表达。
- [ ] 未出现宠物医院、医疗诊断等医疗化表达。
- [ ] 未出现英文为主的主界面。
- [ ] 未使用强赛博荧光风作为主视觉。
- [ ] 未把后台管理表格式布局带入用户端页面。
- [ ] 页面仍围绕“生成自己的宠物数字形象”主线展开。
- [ ] 免费层、广告试用层、付费层边界表达清楚，没有互相混淆。
- [ ] 官方示例模型被表达为免费体验能力，不被表达为真实宠物生成结果。
- [ ] 结果优化仍限定为结构化反馈、定向补图和规则内优化。
- [ ] 细节补色仍限定为贴图层局部颜色与小面积瑕疵修补。
- [ ] 未暗示可自由修改体型、脸型、耳朵、尾巴等模型结构。

## 3. 页面结构与导航检查

- [ ] 开发路由仍以页面为主，页面状态未被默认拆成独立路由。
- [ ] 弹窗仍作为当前页面内组件，不新增独立弹窗路由。
- [ ] 支付成功 / 权益到账仍作为支付页内部状态。
- [ ] 修改昵称、退出登录确认、删除作品确认仍作为弹窗组件。
- [ ] 底部 tabbar 只出现在作品页、案例页、我的页。
- [ ] 二级及更深页面没有底部 tabbar。
- [ ] 页面返回、取消、失败重试路径清楚，不造成用户迷路。
- [ ] 分享落地页和分享转化页没有越权承载结果互动、上传或付费动作。
- [ ] 案例页、搜索页、视频详情页、案例详情页没有演变为社区内容流。
- [ ] 我的、帮助、反馈相关页面保持辅助职责，不承载主创作链路。

## 4. 视觉 Token 与样式检查

- [ ] 页面整体保持温和、干净、治愈、宠物友好、可信、轻科技感。
- [ ] 背景以奶油白 / 浅米色为主，未使用大面积纯黑、深蓝、强紫或高刺激配色。
- [ ] 主按钮使用暖橙色，并只服务于当前页面最重要的主操作。
- [ ] 成功、权益保留、次数未扣减、可恢复信息使用柔和浅绿色或可信提示卡表达。
- [ ] 风险、失败、删除提示使用柔和红棕或温和警示，不制造强焦虑。
- [ ] 颜色、阴影、渐变、圆角、间距优先使用项目统一 token 或公共样式。
- [ ] 新增样式避免继续扩大硬编码颜色和重复阴影。
- [ ] 页面样式没有形成单一色相堆叠或强营销海报感。
- [ ] 文案、按钮、标签在常见手机宽度下不溢出、不重叠。
- [ ] 页面信息密度适中，不像后台管理系统或复杂表单。

## 5. 按钮与操作层级检查

- [ ] 同一页面首屏只突出一个最重要的主操作。
- [ ] 次要按钮与主按钮有清楚层级差异。
- [ ] 删除、退出等风险操作不使用大面积强红，且有二次确认。
- [ ] 按钮文案直接表达动作，避免模糊营销语。
- [ ] 与权益、扣次、支付相关的按钮附近有必要说明。
- [ ] 禁用、加载、处理中状态清楚可见。
- [ ] 重复提交、重复支付、重复生成有状态保护或明确提示。
- [ ] 用户取消操作时，不误导为失败或消耗权益。

## 6. 卡片、状态提示与空态检查

- [ ] 卡片只用于承载明确的信息组，不把页面整段内容塞进复杂卡片堆。
- [ ] 状态标签短、清楚、可读。
- [ ] 空态有下一步动作，不只展示空白说明。
- [ ] 加载态说明当前正在发生什么。
- [ ] 失败态先解释原因，再说明权益 / 次数是否保留，最后给恢复动作。
- [ ] 权益到账、权益保留、次数未扣减等高敏感状态有独立提示。
- [ ] 空态、失败态、异常态没有引导用户重复付费或重复观看广告。

## 7. 核心链路页面检查

核心链路至少覆盖以下页面：

- 作品页
- 开始创作页
- 广告解锁页
- 上传页
- 生成等待页
- 结果互动页
- 定向补图页
- 细节补色页
- AR guide
- 支付页
- AR 展示页
- AR 失败页
- 异常恢复页

每个核心页面至少检查：

- [ ] 页面主任务是否单一明确。
- [ ] 首屏是否只突出一个最重要的主操作。
- [ ] 规则说明是否没有压过主内容。
- [ ] 状态提示是否清楚表达下一步。
- [ ] 失败、异常、权益保留、次数不扣减是否有明确文案。
- [ ] 二级及更深页面是否没有底部 tabbar。
- [ ] 当前页面是否没有承载职责之外的功能。
- [ ] 当前页面的主要出口与条件出口符合页面结构文档。

## 8. 权益、扣次、失败恢复文案检查

- [ ] AR 权益表述为“当前宠物作品”或“当前作品”的 AR 展示权益。
- [ ] 未将 AR 权益写成账号权益、会员权益、全部作品通用权益。
- [ ] 已购当前作品 AR 后，可反复进入 AR，不引导重复支付。
- [ ] 同一作品后续优化、定向补图、细节补色后，仍继承已购 AR 权益。
- [ ] 不同宠物作品之间 AR 权益不互通。
- [ ] AR 失败后明确权益保留，不引导重新支付。
- [ ] 有效优化提交后只预占优化次数。
- [ ] 优化成功返回可用结果后才正式扣减。
- [ ] 系统异常、生成失败、页面中断、结果未成功返回时不扣减。
- [ ] 用户仅选择反馈、查看建议、取消反馈时不预占也不扣减。
- [ ] 细节补色不消耗重新生成类优化次数。
- [ ] 广告试用权益与 AR 付费权益没有混写。
- [ ] 支付失败、支付取消和支付成功但权益确认中有清楚区分。
- [ ] 异常恢复页不处理付费后 AR 展示失败；AR 失败页不混入试用链路异常。

## 9. 表单与上传体验检查

- [ ] 正脸、侧面、全身照片被表达为推荐素材结构，不是强制三张上传。
- [ ] 上传页未上传态突出主上传入口。
- [ ] 无图时不展示“批量管理”“清空全部”等无效操作。
- [ ] 质检结果只突出当前最重要的问题。
- [ ] 达到最低生成标准后，继续生成按钮清楚可见。
- [ ] 素材偏少但可继续时，文案表达为“补充更多照片可能更像”，不是硬性拦截。
- [ ] 素材不可用、权限异常、上传失败有可执行的恢复动作。
- [ ] 定向补图页说明本次补图原因、对应反馈维度和建议视角。
- [ ] 投诉与反馈页保持轻量，不承诺即时解决或自动退款。

## 10. 分享、作品、案例页面检查

- [ ] 作品页仍作为默认首页，承接当前作品、无作品引导和已生成作品入口。
- [ ] 作品详情页不直接承载支付动作、广告观看或首次上传。
- [ ] 删除作品前明确提示该作品及对应 AR 权益将不可继续使用。
- [ ] 案例页只用于效果预期建立，不显示点赞、评论、关注、粉丝、排行榜等社区信息。
- [ ] 视频详情页是单个 AR 成果预览，不做短视频信息流。
- [ ] 官方示例模型体验页明确不等于真实宠物生成。
- [ ] 分享落地页可区分原作者回看和新用户进入。
- [ ] 分享转化页只做预览、理解和转化，不让新用户直接进入结果互动页。

## 11. 我的、帮助、反馈页面检查

- [ ] 我的页不出现会员中心、积分中心、勋章系统、任务中心。
- [ ] 权益说明页明确免费层、广告试用层、优化次数规则、当前作品 AR 权益和失败补偿。
- [ ] 帮助页分类清楚，覆盖上传与生成、优化次数、AR 使用、支付与权益、失败与恢复。
- [ ] 帮助详情页内容分段清楚，避免大段密集文字。
- [ ] 投诉与反馈页反馈类型、问题描述、截图和联系方式层级清楚。
- [ ] 联系我们页只提供联系渠道，不承载投诉进度或即时客服承诺。
- [ ] 个人信息页保持轻量账户管理，不加入复杂账户体系。
- [ ] 修改昵称与退出登录仍以弹窗方式完成。

## 12. 性能与资源检查

- [ ] 新增图片资源经过压缩，避免明显增加小程序包体。
- [ ] 未新增无用大图、重复图、临时设计稿或未引用资源。
- [ ] 页面首屏关键内容不依赖过多装饰图。
- [ ] 高风险页面样式体量有下降或至少没有无理由增加。
- [ ] 大段重复 WXSS 有合并或 token 化计划。
- [ ] 3D / AR 相关页面不新增阻塞首屏的重资源。
- [ ] 列表页、案例页、作品页的空态、加载态和失败态不会造成布局跳动。

## 13. 每批提交前检查项

- [ ] 已确认本批属于第几批，以及允许改动范围。
- [ ] 已确认本批不提前处理后续批次内容。
- [ ] 已确认没有修改不该修改的页面、路由、云函数或配置。
- [ ] 已按 `AGENTS.md` 和三份核心 docs 核对产品边界。
- [ ] 已按本清单核对产品禁令、权益规则、扣次规则、上传规则。
- [ ] 已更新 `docs/ui_optimization_progress.md` 对应批次记录。
- [ ] 已执行 `npm run check`，并记录通过或失败原因。
- [ ] 如涉及 UI 页面，已列出需要人工预览的页面。
- [ ] 如存在遗留问题，已写入进度文档的遗留问题池。
